# Local PG17 RLS and source ledger composition

Run `node experiments/pg17-rls-source-composition/verify.mjs` for the complete old RLS and source ledger matrices plus a same-database invitation/entitlement/RLS/ledger scenario. Run with `--red` for independent compatibility failure observations. Run `node experiments/pg17-rls-source-composition/verify-lifecycle.mjs` for hostile environment, actual SIGTERM, actual startup failure and actual connection failure observations.

The runner uses the frozen local PostgreSQL 17.4 Harness and reviewed replay. It creates a socket-only temporary cluster with bounded connection, query, lock, subprocess and whole-run waits. Every run writes a unique redacted JSON report, retains failed runs, fingerprints inputs before/after execution and stops the server, closes clients and removes temporary files. PostgreSQL logs are hashed but not published because error CONTEXT can contain private captured routine bodies.

`fixture.mjs` directly materializes the fixed metadata selection: seven prior public tables and 13 routines, the complete 34-column stories relation, its fourth reviewed update trigger, Storage buckets/objects including nullable fields, generated path tokens and actual partial unique indexes. All selected columns/ordinals, constraints, indexes and reviewed triggers are catalog-checked. Storage ordinal 13 is represented by a dropped inert placeholder. Storage's enum is an explicitly partial STANDARD-only local shim. Seven Storage triggers whose bodies were not captured are omitted and enumerated in each report. Auth, identity GUCs, foldername and UUID support are local shims; this does not reproduce complete Supabase, JWT verification, Storage HTTP or production role inheritance.

`compatibility.mjs` applies six exact frozen SQL statement adaptations and one exact candidate database-name guard substitution. Independent RED probes establish positional INSERT failures, required projects.name, actual updated_at changes and Storage ON CONFLICT 42P10 before adaptation. The old ledger adapter itself is imported unchanged. Only its old test hash excludes updated_at; a separate test proves that the reviewed trigger runs and every other business/source column is unchanged. The actual TypeScript media projector is transpiled using the installed pinned TypeScript dependency into the temporary directory.

Old ledger and RLS use distinct seeds in explicit phases, followed by a separate end-to-end seed in the same live fixture. Ledger's intentional source-project mutation races run before installation of the RLS candidate's immutable-story-identity trigger. A retained failed composition demonstrates the 42501 conflict if those phases are reversed; no candidate is weakened to accommodate the old test. The final composition grants a trusted source, sends and accepts an invitation, exercises management reads and story/object RLS, denies another family, revokes the source, proves next-statement refusal in an existing READ COMMITTED session, and rejects a subsequent ledger bind. Seven original write RPCs and direct wallet/member writes must still fail with 42501. The frozen RLS test also records the REPEATABLE READ snapshot limitation.

`input-pins.json` fixes source inventory, Node executable, loaded CommonJS/package manifests and installed PG bin/lib/share. `pin-inputs.mjs` is an explicit development tool to regenerate those pins after reviewable local edits. It is not invoked by verification. Private capture paths/hashes are verified but their contents never appear in reports. The installed runtime still depends on ambient macOS system libraries and kernel. Source digest examples apply to this PG17.4 representation; no universal cross-version stability is claimed.

No app sources, dependencies, root migrations or old evidence are edited. No remote database/provider/device calls, commits, pushes or deployments occur. Real-device validation is deferred, not passed; local evidence does not clear the original release gates.
