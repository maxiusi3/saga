## 1. 断点与实际交付

延续上一批 handoff 的第一个剩余工程项，不重新创建已经存在的组件、迁移或 PG 实验。中途恢复时，页面、浏览器适配器和服务端路由均有未提交修改；type-check/lint 通过，没有新 SQL。实际断点属于情况 B：规格审查新增回归尚有失败，浏览器与全工作区验收尚未完成。保留全部未提交内容、RED 日志和历史证据。

- 实际项目页改为同步 server wrapper；只把 `MEDIA_ASSETS_ENABLED === 'true'` 的布尔值交给客户端。真实项目加载后才挂载 hub，默认关闭时不调用新接口。
- 原项目列表、筛选和角色界面保留；移除加载失败时的虚构项目回退、私密项目/故事调试日志，以及重复导出空按钮的可点击假象。
- 上传使用登记、非覆盖签名上传、complete。保留用户 File 和幂等键供显式重试；`uploaded` 重放继续校验，已知新版 409/旧版重复对象 400 通过 complete 核对，不覆盖已有对象，不放行其他 400。
- 音频 `verifying` 明确显示待校验，保留原文件，不触发 AI、不宣称解码成功。录音和邀请导航复用已有 locale 路径。
- 搜索发送当前身份与筛选项；回听只接受真实 `mediaAssetId`。加载 metadata 后定位，时间段末尾暂停；新搜索和项目/账号切换撤销旧结果与音频，卸载清理下载 URL。
- 服务端复用中央身份/项目权限检查，删除证据缺失或截断时拒绝读取。导出不追加原始旧 stories 全集，旧媒体未映射返回 409，最终在异步压缩完成后再次检查成员权限和墓碑。
- 真实索引表没有 `media_asset_id` 或 `story_title`；检索使用 `transcript_versions.asset_id` 和实际 stories 标题，核对项目/故事关联。无可验证来源、未绑定或非 ready 的旧索引完全不展示，不能把不支持回听的旧文本误当已验证资料。项目级导入必须完成后续故事关联/校验/索引链才可检索。

## 2. 有界导出与未实现边界

同步导出最多 200 篇故事、100 个资产、25 MiB 原件、2 MiB 元数据。原件逐流读取并检查累计上限、字节数与 SHA-256，既有 assembler 生成离线目录、清单和 PDF；超限返回 413，不静默生成部分档案。客户端解析 ZIP 容器结构，不在浏览器解压所有媒体或重算全部原件哈希。浏览器 Blob 接受上限为 32 MiB。

此限制不是 T09 大包 Worker 的替代品。没有新建音频解码 Worker、持久导出 Worker、索引写入链、监控采集/告警投递、供应商资格服务。导入待校验音频不会自动变成可检索的故事。

额外只读核对至多 1000 条转写版本来源记录；来源读取不完整失败关闭。旧 stories 文字没有精确版本归属，若任何已知转写/旧关联音频来源删除或无法确认，整包返回 409，避免 HTML/PDF 保留已删音频的派生文字；不因独立照片删除就丢掉故事文字。

权威墓碑字段是 `deletion_requests.tombstone_at`；当前根迁移没有 `media_assets.tombstone_at`。路由使用实际表结构，不能凭测试夹具虚构数据库字段。已签出的短期链接仍受其 TTL 限制，离线副本无法远程撤销；本批没有宣称跨数据库与对象存储的全局原子撤回。

## 3. 审查与回归

- 首轮前端规格审查发现截断 ZIP 和新搜索残留旧音频，新增回归真实 RED 为 4 项失败；修复后通过。
- 整体规格审查发现 `uploaded` 重放漏接（RED 1 项失败）、Storage 新旧错误格式兼容（RED 5 项失败）与压缩期间删除/撤权（RED 2 项失败）；修复后组合定向回归 12 套/159 项通过。最终 Task 1–3 静态规格审查 PASS。
- 初次浏览器 12 项通过后，人工查看 375px 截图发现搜索按钮超出表单但未超出 viewport；增加更严格几何断言后真实 RED，修复为窄屏纵排、输入框可收缩。旧通过报告和新失败报告均保留，不以旧报告替代最终重验。
- 独立质量审查另发现三项真实问题：索引夹具虚构媒体字段、删除音频后导出仍带派生文字、省略大小的登记重放错误比较已测大小。改用实际 schema 来源关联、删除派生访问失败关闭和可选大小语义；RED 分别 25/11/2 项失败，定向 GREEN 分别 37/42/35 项通过。
- 最终命令链 `npm run verify && npm test --workspace=packages/shared -- --runInBand && npm run test:infra` 退出 0：Web 130 套/1657 项、shared 4 套/16 项、infra 7 项、184 页构建。最终 Chromium 1440/375px 共 12 项通过，截图人工检查通过，无外部请求和 pageerror；汇总与完整日志见本轮 `verification.json`。
- 构建仍提示服务端 Supabase key 缺失、Next 旧配置及 images.domains 弃用；本轮未运行 audit。不能将构建成功解释为部署配置或依赖审计已经合格。

## 4. 证据范围

浏览器脚本加载真实 hub/controller/client，认证、Next Link、Storage SDK 边界和 HTTP 响应使用本地合成夹具；使用生成的六秒 WAV 和真实 ZIP，禁止外部网络请求。它不是 Next 服务端 E2E、真实 Supabase Storage/Auth 资格或手机硬件证明。

原样重跑 PG17 切流（3 场景/23 断言）与 P3（4 场景/51 断言），均 passed/退出 0。新 JSON 从旧输出目录移到本轮目录，旧文件和脚本不改。冻结 runner 将 `Harness.cleanup()` 的 undefined 返回值覆盖报告字段，首个采集 wrapper 因 `KeyError: cleanup` 失败；原 passing 报告保留，改用独立 scratch/PID 不存在核对后重新采集两轮，见 `pg17-reruns.json`。没有为修复报告格式去修改冻结代码。
