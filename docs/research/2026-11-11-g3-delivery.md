## 实现与关闭的问题

**归档交付（T09）。** 导出原先读取旧 `stories.transcript`，PDF 截断正文并丢失中文，每次下载产生新的 v1 与托管期限。现在读取 G2 已批准版本，单独标记原始转写和来源版本；草稿不能冒充已批准传记。持久快照固定身份、版本、原件清单与 PDF 哈希。同一来源重复请求复用快照，来源改变生成新版本，历史批准记录保留。快照的 `hostingRetention` 为 null；购买后分配项目的测试托管窗口由 `payment_project_rights` 保存，下载不会创造或延长它。

PDF 使用带 SIL 授权的 Noto Sans CJK SC 字体完整分页，并在输出前检测缺字，失败时明确报告。大归档进入持久任务，由 `worker:publications` 在私有共享磁盘流式处理原件和 ZIP；页面显示排队、执行、失败、重试和下载。任务有领取令牌、串行心跳、九分钟截止时间、过期恢复与最多五次尝试。下载在读取 ZIP 后重新核权限、来源与墓碑。G1 删除会同步清除快照／任务并持久排队删除文件，恢复后的孤立文件也会重扫。

独立复审修复了两处 P1：旧 `project_members` 行可能绕过 `project_roles` 撤权，以及批准后替换音频仍可能把旧正文打包为批准版本。独立原生复核分别返回 `42501`、`23505`；综合运行也覆盖这两个反例。

**来源检索（T10）。** 当前查询直接投影转写版本、分段、审阅决定和当前来源指纹，不依赖手工填写的旧索引正文。查询有故事、分段、正文和返回数量边界，支持关键词／人物／年份／地点字面匹配。家庭补充、争议及未对齐文本保持无时间码；只有真实原声段落提供播放。播放接口在签名等待前后核对整组引用身份与当前权限，纠正转写后的旧引用返回 409。界面明示来源匹配，语义检索仍为 `unavailable_unmeasured`。复审发现的 Unicode 标题 UTF-16 长度误判已修复并独立复跑。

**支付履约（T11）。** 活动购买页为 US$59 单讲述者项目，明确测试模式及待确认的真实商业条款。服务端保存订单／请求身份，通过真实 Stripe SDK 验证原始签名，并核对模式、支付单、订单、付款人、商品、金额和币种。重复、并发、失败、取消、未知响应和乱序回调有持久处理；全额退款只撤销该来源的权益。部分退款先于成功进入 `refund_review`，不发新权益，不冒称已全额退款。超过 Stripe 幂等保留安全窗口的未绑定订单要求对账，不自动新建支付。

订单分配可绑定已有自有项目或创建新项目，重试复用项目与固定测试托管时间。可信邀请／权益依赖正式进入根迁移，没有把旧钱包余额当作付款证据。新账户不再赠送无来源券；旧创建页改由可信分配处理。复审还实际复现并修复了直接 INSERT 项目绕过付费 RPC 的 P1：表和列的 INSERT 权限均撤销，可信分配仍成功。支付请求体改为按真实流字节限制，账号切换后的旧购买响应不会进入新账号界面。

**集成与恢复（T12）。** 部署迁移清单包含三份新迁移，Next 构建确认包含字体资产；本地 Supabase 配置增加受限邀请 RPC schema，权益内部 schema 保持私有。完整数据库备份覆盖公共支付／出版表及两个可信来源 schema；归档私有卷另存路径／长度／哈希清单。真实恢复逐表比较数据后重放删除，验证被删 ZIP 消失、另一份归档哈希不变。
