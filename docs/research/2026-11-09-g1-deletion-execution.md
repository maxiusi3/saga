## 实现和修复

新迁移增加执行、永久 fence、对象观察和事件四个私有账本。原 `deletion_requests` / `deletion_targets` 保持原行、hash 和重放语义。现有删除租约仍然只协调所有权；新执行 RPC 才产生带 run 身份的对象操作。调用前检查完整捕获摘要，旧 worker 和未观察过对象的 dispatch 被拒绝。

引用守卫从捕获时生效，防止资产转挂故事、会话改上传者、永久地址复用及 service-role 迟到写入。未选中的派生资产/旧引用存在时返回 `blocked_reference`。已知 `/api/media/assets/<uuid>/play` 按资产解析，因此无关现代故事可以继续保存；被选中故事中未捕获的旧 URL/图片也会阻止执行。修复了独立审查发现的“所有非空 URL 都误判为旧引用”“捕获后转挂资产仍可删”问题。

Worker 删除精确对象地址，随后从会话前缀起点重新盘点直到空列表，处理未封口登记的迟到数字分块。删除之前必须有本轮 present 观察；删除结果和随后不存在的观察分别落库。丢响应、进程在 dispatch 后退出、底层删除失败、present 后竞争删除导致 not_found 都保留物理未知，后续 API 404 不会覆盖成成功。

已加入 `npm run worker:deletions`，支持离线 `--check`、一次运行及持续扫描、SIGINT/SIGTERM 收尾和固定状态日志。需要显式环境配置；不会隐式加载 `.env` 或创建远端设施。操作说明见 [Worker 文档](../media-deletion-worker.md)。

## 结果边界与 G1 状态

`observed_absent` 只表示记录时刻 **Storage API 命名空间不可见**、本轮前缀盘点为空且无已知物理操作未知。所有回执继续 `physicalDeletionComplete:false`。Supabase API 不能发现没有元数据的底层孤儿字节；未知旧上传形成的这类对象需要供应商侧 inventory/cleanup。周期清理覆盖 API 可见迟到对象，不能当作后台所有版本和备份已擦除证明。
