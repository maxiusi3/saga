# UR Saga 产品与用户体验调研：英语市场家庭

> **2026-10-08补充：** 代码核查仍以10月7日为准。新的[社交讨论研究](2026-10-08-social-and-market-strategy.md)增加了已有声音导入、家人陪同采访、沿用既有沟通渠道及不同记忆版本的验证方向。“长辈独立完成”与“家人陪同完成”应分别统计；陪同不自动视为产品失败。

调研日期：2026-10-07。范围：读取 `CLAUDE.md`、`UR saga v1.8.md`，追踪当前 Next.js 实际路由及其使用组件，并于当日通过 curl 读取 W3C / MDN 官方资料。**这是静态实现审查和研究建议，未开展真人用户测试、真机录音测试、线上交易或私密家庭数据访问；不是无障碍合规认证。** 以下“已实现”表示代码存在且接入所述路径，不等于生产环境已经通过验收。

## 1. 结论：理念没有过时，体验承诺领先于闭环实现

“让家人留下自己的声音，并让下一代容易找到、听见和理解”仍然是明确的用户价值。PRD 在 2025-12 的 v1.8 已由文字书转向有声内容，之后又加入可留存的 Agent 产物；不能把当前项目当成建立之日冻结的产品。真正需验证的是：家庭愿不愿意持续讲述、成年子女愿不愿意为最终成果付费，以及录音、修订、保存、交付是否足够可靠。

面向英语市场，建议首批仅服务一个具体场景：成年子女为父母或祖父母整理一组可分享、可下载、保留本人声音的家庭故事。组织者购买和管理，讲述者录音，其他家人听取和补充。市场地理范围仍需明确；英语并不意味着所有家庭具有相同的口音、数字能力、付款习惯或法律环境。

值得保留：网页邀请、原声、私密项目、家人评论、AI 干预可关闭、修改故事后重算编辑产物。最需修复：跨会话恢复、导出交付、真实音频处理状态、录音与隐私选择的文案。公共历史档案是第二种用途，应在私密家庭成果被验证后独立推进。

## 3. 优先级：先兑现家庭信任，再增加智能体验

### P0：公开收费或扩大录音试点前完成

**A. 录音恢复必须端到端成立。** 当前 `SmartRecorder.tsx:79` 的 session ID 只在内存，IndexedDB schema (`lib/recorder-db.ts:3`) 只记录块及 session，不包含项目、讲述者、题目和完整会话状态。旧 `RecordingDraftRecovery.tsx:43` 用 localStorage 保存对象 URL，且搜索当前代码未见该恢复组件被主录音页挂载。不能将“存在恢复文件”等同于“恢复可用”。建议每块先持久写本机，再异步上传；保存会话清单、块顺序、真实 MIME 类型和完成状态；重新打开页面明确显示“已保存到此设备 / 已备份到云端 / 待发送”。只有最终故事确认后才清理草稿，并给用户本地下载退路。需要验证块重组产生可解码的完整文件，不能假定每个片段本身都可独立播放。

**B. 导出是产品价值，不只是高级功能。** 设置页导出按钮只提示成功性质的 toast。已有 ZIP API 也不含音频/照片。在 `api/projects/[id]/export/route.ts:85` 写入 Beta README 后，`:207` 再写同名 README，将原先“不含音频照片”警告覆盖。建议最小交付为原声文件、校对文本、图片、标题日期和可离线打开的目录；用另一台设备断网后验收。等该链路完成再宣传“保存你的声音”“家庭永久拥有”等具体权益，并写清托管与下载的区别。

**C. 删除没有处理凭据的完成标记。** `ReviewStage.tsx:35` 把 isAutoLeveling 初始化 true，`:64` 因此显示 “Auto-Leveling Applied”；本组件未调用音频响度处理、未读取处理结果。麦克风或浏览器的自动增益不等于成品母带处理。该标签应由真实处理产物状态驱动，否则改成准确的原声试听。

**D. 避免第一次保存时误选公开。** `ReviewStage.tsx:122` 将 Private / Public 并排切换，Public 文案是 “Visible to everyone”；另一方面项目另有匿名公共档案贡献流程。界面上仍容易把“家人能看”“全网公开”“匿名参与历史档案”混淆。第一次录音建议默认仅项目成员可见，展示具体受众。公开应有单独预览、解释、确认和撤回，不能用一个开关替代知情选择。这里指出的是认知与文案风险，并未声称此开关已经造成线上泄露。

### P1：第一轮家庭测试中优化

1. **把讲述者首页收敛为一个问题、一个录音按钮。** 第一次就要求选两种模式和 AI 强度，会让用户先理解系统再讲故事。将 2–5 分钟短故事作为默认试点方案，深聊和 AI 选项折叠；这是待测设计假设，不是已证实最优时长。
2. **邀请后的目的地应是待回答的问题。** 保留安全认证，但完成认证后回到受邀上下文；允许组织者预设问题和熟悉照片。失效邀请应提供清晰重新联系邀请人的路径。
3. **对模糊记忆保留模糊性。** `ReviewStage.tsx:34` 默认 today，`:97` 要求日历日期。讲述 1960 年代往事时容易无意留下当天日期。支持“不确定 / 大约年份 / 年代 / 以后由家人补充”，区分发生时间和录制时间。不要用 AI 推断制造精确日期。
4. **浏览器失败不应只变成打字。** 当前录音页 `:116` 通过错误字符串识别权限问题，随后进入文字备选页。建议先展示该设备允许麦克风的步骤、重试，以及上传已有录音；打字作为另一个选项。对无法打长文的人，纯文本兜底不等价于任务完成。
5. **让错误核对围绕故事事实。** 将 “Editor Agent Review”“Normalized”“Offsets”“confidence” 从家人默认阅读面板转换为“整理后的故事”“需要您确认的姓名/年份”“听这一段”；保留原声与逐字稿，不以模型置信度数字冒充真实准确率。现有来源引文可复用到核对流程。
6. **给保存和处理以可理解的状态。** “已保存录音，文字正在整理”与“整理失败，录音安全”必须可区分；家庭成员之后可重新打开成果，失败可重试且不重复创建故事。

### P2：证明完成率后再扩大

公开历史共鸣、更多 Agent 角色、八种语言、复杂实时语音对话，都应服从核心家庭闭环。英语优先意味着先验证美国/英国等目标地区实际设备、英语口音、移民家庭专名及混合语言，不必立即扩展所有语言。AI 主持可以测试，但不应把“愿意对 AI 说话”当作默认前提；一部分人可能更愿意回答子女录好的问题，或让亲属在旁访谈。

## 4. 适老体验：采用标准，但不要把老年人视为同一种用户

- 主按钮建议 44–48 CSS px 或更大，暂停/结束动作分开，文字标签与图标同时出现。**这是产品建议**；WCAG 2.2 AA 2.5.8 的最低目标大小是 24×24 CSS px，且有间距等例外 [S1]，不能把 44 px 写成 AA 普遍门槛。
- 字体建议正文从 18 px 起做真机验证，支持浏览器放大、键盘操作、清晰焦点、屏幕阅读器标签、充分对比。当前未测像素、对比度和屏幕阅读器，不能判定达标或不达标。
- Magic link / OAuth 有助于减少记忆密码负担，但邮箱应用切换是否顺利必须观察。WCAG 3.3.8 针对认证中的认知测试，要求替代方式或辅助机制等；并未要求完全取消认证 [S2]。
- 不用“你讲错了”纠正记忆。展示“这里听起来像 X，您愿意确认吗？”；允许跳过、不回答、停止、删除，以及家人意见分歧并存。
- 主状态持续可见：是否录音、是否暂停、声音是否被检测到、已保存多少。不要只靠红点、动画或短暂 toast 传递关键状态。
- Wake lock 是防止屏幕休眠的协助机制，不是系统后台持续录音保证。页面不可见、系统策略等可释放锁；MDN 建议处理释放并更新 UI [S3]。现有重新可见时申请锁是合理基础，但需清楚告知中断并验证实际音频。
- `MediaRecorder.start(60000)` 不保证每 60 秒准时落块。MDN 明确列出 Safari 暂停麦克风及 Android Chrome 锁屏延迟 dataavailable 的情况 [S4]。因此“最多只丢 60 秒”不能在未验证的情况下宣传。
- 浏览器 SpeechRecognition 在部分常见浏览器不可用，Chrome 等可能通过服务端处理且不能离线运行 [S5]。私密承诺应解释实际语音处理方，离线模式应明确只有录音可继续，不能承诺所有 AI 功能离线。

## 5. 真人试点：两周内回答“家人是否完成并再次使用”

建议 8–12 个英语家庭，每户至少一个组织者与一个讲述者。覆盖 60–69、70–79、80+ 岁、不同数字熟练度、至少一种辅助使用需求；不要把年龄当成能力代理。样本用于发现问题，不用于宣称市场占有率或人口统计结论。设备覆盖 iPhone Safari、Android Chrome、桌面主流浏览器及常见短信/邮件内打开方式。技术破坏测试先用虚构故事和测试账号，不让真实用户承担丢失珍贵录音的风险。

**每户首次 45–60 分钟：**

1. 组织者邀请一位亲人：“请请他/她讲一个你想留下的故事。”观察理解价格、谁能听、最终拿到什么；不先演示操作。
2. 讲述者在自己的手机打开邀请并开始一分钟故事。记录首次有效录音用时、跨应用切换次数、求助点、误触；让用户解释麦克风权限和故事受众。
3. 讲述中暂停、恢复、试听、保存。观察是否知道当前状态，是否担心录音丢失，是否把结束和删除混淆。
4. 用含一个专名和模糊年份的虚构故事检查转写。让家人找到错误、听对应原声、修正，并确认不会因此丢掉原稿。
5. 将故事发给另一位家庭成员，让其听取、留言一个追问；一周内回访是否真的完成第二个故事。
6. 组织者下载成果，并在另一设备离线播放原声、查看文本。询问若停止订阅，认为哪些东西仍属于自己；据此检查产品承诺理解是否一致。

**另做可重复真机故障矩阵：** 录音 5/20/30 分钟、弱网/断网恢复、切换应用、锁屏、来电、刷新/关闭重开、拒绝权限后重试、空间不足、上传失败、AI 超时、重复点击保存、邀请过期。逐项核对音频是否可解码、段落顺序、时长、恢复入口和重复故事，不只看成功 toast。

**建议预先登记验收门槛，以下不是行业基准：** 首次独立完成率 ≥80%；在声明支持的故障场景中已确认保存的音频零丢失；所有参与者能说明私密/公开范围；100% 测试家庭能离线打开交付包；AI 导致姓名、关系、日期改写的高严重性问题全部人工确认。小样本不稳定，应报告分子/分母，例如 9/12，而不只展示百分比。

核心业务指标建议为“每户每周新增、家人实际听取且可导出的有效故事数”，配合首次完成率、第二故事率、邀请成功率、求助次数、修订时间、录音恢复成功率。录音总分钟数和 AI 调用次数不能单独证明用户价值。
