## 结论先行

**UR Saga 不需要因为建立时间早而推倒重做；需要重新验证定位，并把“采集家庭记忆”真正做成“家庭能够完成、信任、带走的作品”。** 现有框架并不陈旧，家人留下原声的需求也没有因为 AI 普及而消失。但“网页录音、AI 整理成传记、保留声音”已经是直接竞争者可购买的产品能力，不能继续把这些当成独特优势。

目前最大的风险有三项：

1. **竞争假设落后于市场。** Storyworth 已提供电话讲述和引导访谈；Remento 的 $99 首年商品已把网页录音、AI 成稿、精装书和二维码原声组合起来。只做一个更好看的 AI 录音工具，竞争理由不足。
2. **产品承诺领先于实现。** 当前已核查导出路径没有交付原声音频和 PDF；跨会话录音恢复未闭环；一些 Agent 是规则与模板，而非文档描述的智能编辑和主持能力。近期“修复完成”的报告不能代替用户路径验收。
3. **商业假设仍待实证。** 本次没有取得真实付费、家庭完成率、退款、获客成本和人工工时数据；等待列表也不能证明长辈愿意参与或子女愿意付款。

**市场推荐明确为：继续英语方向，美国作为首个主要付费试点；若其他英语地区有明显更强的实际招募渠道，则调整国家先后。** 本次没有同口径的其他语言市场数据，不能宣称英语/美国全球最优，也没有依据建议改做中文市场。

产品上用现有底座比较两个入口：**先保存已有语音/视频片段**，以及**由家人陪同或长辈独立完成几次短讲述**。原来的“四周小故事集”保留为后者的试验范围，不再假设所有人都想先写一部传记。AI帮助提问、整理和核对；讲述意愿、家庭回听和可独立保存的成果比模型名称更重要。

这里的“短周期完成＋原声可追溯”和“已有声音整理”都是值得测试的定位，不是已经证明的护城河，也不能宣称竞品均没有这些能力。

证据：Git 历史；[PRD](../../UR%20saga%20v1.8.md) 修订表；[最近会话总结](../session-2026-10-07-summary.md)。

### 2.2 产品的四种角色

- **购买者/组织者：**通常是成年子女，买的是“这件事有人帮我完成”，同时希望与父母产生连接。
- **讲述者：**贡献声音、时间与私人经历；他/她是否愿意讲，不取决于子女是否已付钱。
- **家庭听众：**听故事、补照片、提出追问；他们的反馈可能比积分、徽章更能推动下一次讲述。
- **公共档案贡献者：**愿意另行授权把部分经历公开的人；这是另一项任务，不能默认与前三者绑定。

现有项目把这些角色都纳入了框架，但对外商品应先解决前三者的私密闭环。公共档案涉及独立授权、审核和长期治理，不能把它的未来网络效应当成当下付费的依据。

### 2.3 保留什么，补齐什么

| 领域 | 当前证据 | 判断 |
|---|---|---|
| Web 底座 | Next.js 16.2.6、React 19、TypeScript、Supabase、npm workspaces | 可以继续用；版本较新不代表依赖或权限无风险 |
| 家庭协作 | 项目、角色、邀请、故事、评论、时间线已有实现 | 这是业务资产，优先复用 |
| 录音 | MediaRecorder、60秒切片、wake lock、失败块 IndexedDB | 有基础，但不等于完整的离线与刷新恢复能力 |
| AI 产物 | Agent runs、故事元素、来源引文、独立原稿/产物结构 | 分层方向正确，适合加真正的模型编辑与人工确认 |
| 当前 Agent | Interview 固定提示/规则；Editor 截取摘要与正则抽取 | 不应把模块名字当成已经完成的智能能力 |
| 导出 | 检查到 ZIP JSON/TXT，设置页按钮仍 TODO | 离“家庭可以保存有声书”还有关键缺口 |
| 商业入口 | 购买页变为 Waitlist，仓库仍有多套套餐/支付配置 | 适合招募验证，不等于付费系统已闭环 |
| 公共档案 | 已有第二阶段设计及实现文件 | 已投入可以保存；不宜继续优先于私密成果 |

## 3. 产品理念：哪些仍成立，哪些需要更新

### 3.1 仍成立的核心

**原声不可替代。** 家庭关心的不只是故事信息，还有声音、停顿、笑声和说话方式。生成一篇更顺的文章并不能替代这些。原录音应当是可保存的一等资产，润色稿只是其上层表达。

**采集的困难是人的动机与过程。** 有些长辈不认为自己的经历值得说，有些子女买了礼物却没时间推动。可行的产品应让第一次讲述足够轻、第一次成果足够快，并让家人真实回应。

**网页邀请降低安装负担。** 但仍有消息、浏览器、邮箱、麦克风权限之间的切换。免 App 是入口优势，不代表零摩擦，也不应绕过授权。

**私密家庭空间有价值。** 家庭回忆中有关系、疾病、迁徙、冲突与他人的信息。购买者希望的是信任与可控，未必希望社交曝光。

这些是合理的产品逻辑；是否能转化为本项目的购买和持续使用，仍要靠家庭试点验证。

### 3.2 需要放弃的旧假设

| 原假设 | 调研后的修正 |
|---|---|
| 对手主要要求长辈写作，语音是我们的独特优势 | Storyworth 也有电话讲述；Remento、Storii 已将语音产品化 |
| 有 AI 转录/总结就能显著差异化 | 它已接近基础能力，需比较完成结果、可靠性和信任 |
| “NPR级音频”适合当 MVP 核心承诺 | 本项目尚未实现且需求未验证；先保证原声清楚、完整、可下载 |
| 公共记忆越多，商业护城河越强 | 私密用户不一定愿意公开；历史资料需要来源与持续治理，量大不自动等于价值大 |
| 功能多、角色多、语言多等于覆盖更大市场 | 会增加首次使用与运营复杂度；先固定一个家庭任务和国家 |
| 终身云端托管能解决所有传承顾虑 | 必须有成本准备、可移交权限、独立导出和停运安排；一句 lifetime 不足够 |

PRD 自身还存在范围冲突：2026-10 修订把 NPR 后期处理推迟，但“质量目标”“最终交付物”与后面的流程图仍写 NPR/母带/有声书。应统一为当前可验收范围，不能只更新修订表。

### 3.3 建议的第一版价值主张

面向成年子女，可以测试：

> **Keep their voice. Finish the stories you’ve always wanted to ask about.**

中文含义：保留亲人的声音，也把那些一直想问的故事真正完成。

具体产品可以测试“四周、一位讲述者、一个主题、几篇完成故事”，例如第一次工作、一次迁居、父母如何相识。**10月8日修订：同时比较已有声音整理入口；四周方案不是唯一用户任务。** 四周是试验设计，不应在具备交付能力前作保证。短范围便于双方理解、执行和验收，也要允许家庭只保存一个片段。

不建议首发承诺逝者数字替身。它改变了产品的伦理、情感和技术任务，且用户当前并未要求。保留原声、检索原声片段，已足以测试核心价值。

## 4. 英语市场竞争：门槛在哪里

| 竞争者 | 当日官方页面确认的能力 | 对 UR Saga 的影响 |
|---|---|---|
| [Storyworth](https://welcome.storyworth.com/storyworth-pricing/) | 邮件问题、电话转录、升级档引导访谈、Family Calls、精装书；价格正文与FAQ冲突 | “不必写作”和“家人协作”不能单独作为差异 |
| [Remento](https://www.remento.co/) | 首年$99；1位讲述者、无限协作者、网页录音、AI整理、380页内彩色精装书、QR原声 | 这是最直接的商品比较标杆；纯数字$99必须解释多出来的价值 |
| [Storii](https://www.storii.com/pricing) | 每周3次计划电话、随时回拨、AI传记重写、有声书与电子书；本次价格未渲染 | 电话可能比网页更省操作；应以实际长辈成功率决定渠道 |
| [Ancestry](https://www.ancestry.com/c/ancestry-family) | 家谱与档案发现；美站Family History正文$24.99/月起 | 争夺家庭历史预算，但使用频次和续费逻辑不同 |

Storyworth 的 Basic/Color 正文为 $69/$99，FAQ 为 $59/$109，Unlimited 为 $199 首年；尚未结账，不能给出唯一确定成交价。HereAfter AI 本次官网404，不能据此断言停运。详见竞品专题。

不要只研究付费软件。**手机录音＋共享相册/云盘＋通用 AI＋家人自行整理**是价格很低的替代方案。UR Saga 必须减少组织、追问、纠错、排版和交付的总劳动，而不只是让某一项模型调用更方便。

值得测试的差异有三种，均需对照竞品或现有办法验证：

1. **更容易完成：**邀请后能开讲，短期内得到首个作品，家人知道下一步做什么。
2. **更值得信任：**原话、编辑、推断清楚区分，人名年份可核对，原声片段可回听。
3. **更能带走：**停订后已有成果不被锁住；下载包在另一设备离线仍能播放和阅读。

这些优势需要长期执行积累：可授权使用的错误评测集、成熟的家庭完成流程、可靠的导出与支持记录、真实推荐关系。用户私密内容不能因为存在数据库里就当作可自由训练或变现的数据资产。

## 5. 用户体验：应先修复的不是视觉风格

### 5.1 当前旅程的主要断点

| 断点 | 代码证据 | 建议验收 |
|---|---|---|
| 邀请后仍需登录并进入项目面板 | `invite/[token]/page.tsx:65` | 在本人设备完成认证后直接回到受邀问题；观察是否需子女代操作 |
| 双模式名称未形成两条不同体验 | `RecorderHub.tsx:39`、录音页`:286` | 默认一个简短故事入口；只展示真正实现的模式差别 |

上表短路径全部相对于 `packages/web/src/`；完整位置与调用链见 UX 专题。另一个明确细节：导出 API`:101` 写入 Beta README，`:207` 又覆盖同名文件，最终“不含音频”的说明不会保留。它说明需要以最终产物验收，而不只检查补丁里是否出现了说明文案。

### 5.2 建议的最短闭环

**子女选择一个问题/照片 → 长辈看到谁邀请、谁能听 → 开始讲述 → 原声安全保存 → AI 整理并标出不确定处 → 家人听取与确认 → 下载第一份小作品 → 家人提出下一问。**

第一版不要求长辈理解项目、钱包、席位、Agent、公共库。复杂管理放在购买者界面。采访可关闭；问题可以来自子女；家庭成员同场采访也是有效方式，不必所有人都面对 AI 独白。**新增平行入口：导入已有录音/视频→补充背景→私密回听→完整下载；先验证它比云盘多解决了什么，再决定是否单独收费。**

### 5.3 适老设计应由观察验证

建议以大按钮、持续可见的录音状态、少量单步指令、文字与声音双重提示、可暂停/跳过、不惩罚慢响应为起点。44–48 CSS px 按钮和18 px正文是可测试的设计建议，不是统一法规门槛。WCAG 2.2 AA 目标最小尺寸要求为24×24 CSS px并有例外，详见 [W3C](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。

浏览器 wake lock 不保证后台持续录音；60秒 timeslice 不保证准时生成块；SpeechRecognition 也不是全浏览器、全离线可用。相关 [MDN 依据](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/dataavailable_event) 已纳入 UX 专题。这些是可靠性设计边界，不是建议直接改做原生 App 的理由。

## 6. 技术与 AI：升级重点应是流水线、评测和真实状态

### 6.1 文档和实际调用已经分叉

文档写 OpenAI/Whisper，但静态代码显示多条路径：

- 主录音组件使用浏览器 `SpeechRecognition` 产生实时文本。
- 服务端 ASR 路由默认请求 `api.siliconflow.cn` 的 `FunAudioLLM/SenseVoiceSmall`。
- 文本处理路径使用 OpenRouter，部分默认模型为 `openai/gpt-oss-20b:free`；环境变量可以覆盖，未检查生产密钥与实际供应商配置。
- Interview/Editor 纯逻辑模块以模板、规则和正则工作；它们已有可复用的产物存储，并不代表已经拥有成熟模型能力。
- `lib/ai-service.ts` 可在服务不可用时返回 mock 转写/内容，其中包含随机示例。这是可调用路径风险，**不代表主录音每次都会经过该分支**。

对于真实家庭记忆，模型失败必须显示“处理失败，但录音仍在”，不能返回似真的样例故事。尤其不能将被编造的人物、年份写入家庭档案。

面向英语用户，应先统一“原声到底怎样到达最终转写稿”的主链路，再选模型。主录音未获得浏览器 transcript 时，必须有服务器补转写与重试机制；不能让浏览器实时字幕成为唯一事实来源。

### 6.2 建议的下一版结构

```text
设备录音 → 本地持久会话与音频块 → 私有对象存储
                                     ↓
                              持久任务/状态机
                                     ↓
                             ASR + 时间戳原稿
                                     ↓
                        结构化提取 + 引文/音频来源
                                     ↓
                         忠实整理 + 待确认问题
                                     ↓
                         家庭审阅 + 原声/作品导出
```

继续使用 Next.js 做交互、认证和任务入口，Supabase 做数据与权限。耗时音频处理和生成放入可重试的后台任务。初期选择一个能满足队列、超时、重试和观测需求的执行方案即可，不必一开始拆微服务或建立复杂多 Agent 网络。

每个故事需要明确状态：已保存原声、等待转写、转写失败、等待整理、待家人确认、已交付。持久化输入版本、模型/提示版本、来源段落、错误原因和成本；幂等重试不能重复生成故事或重复收费。现有 agent run 和内容哈希可以复用。

结构化输出只能约束格式，不能保证事实正确。编辑稿出现原稿里没有的人、地点、动作或结论，要标出/拒绝，而不是自动接受。年代冲突保留双方说法；不应默认用模型常识覆盖个人记忆。

### 6.3 AI 能力按收益排序

| 能力 | 建议优先级 | 升级理由与边界 |
|---|---|---|
| 英语录音可靠转写、专名提示、时间戳 | 立即 | 所有后续成果依赖它；比较错误与纠错时间，不只比较价目表 |
| 忠实整理、提取待确认信息 | 立即 | 降低子女劳动且保持本人声音；使用来源校验与人工确认 |
| 根据已讲故事生成一个有用追问 | 近期 | 可异步生成，不必马上做全双工实时 AI |
| 照片上下文辅助提问 | 近期小范围 | 让家人确认人物和年代；不能从照片臆断身份或历史事实 |
| 实时语音主持 | 通过对照试验后 | 测是否提升完成率；同时测打断、等待、长停顿和成本 |
| 降噪、均衡、音频编辑 | 按实际回听障碍推进 | 先保留原声；不要自动删掉有情感意义的停顿和笑声 |
| 公开事件聚类、媒体生成、多角色自治 | 后置 | 不解决当前录音与交付断点，且增加另一套审核与成本 |

最新模型、官方单价、数据控制与替代供应商的核实结果见 AI 专题。**不建议把某个模型名称写死为产品优势。** 用英语老年录音评测结果决定主供应商，固定上线版本，再定期在固定数据集上比较候选版本。

### 6.4 一个能决定模型采购的评测集

在得到明确使用授权后，建立约30–50段短录音，覆盖英语口音、轻声/缓慢语速、长停顿、家庭噪声、插话、专名、模糊年份和自我纠正。先用虚构素材做破坏性测试，再引入同意用于评测的真实样本；与营销公开授权分开。

至少比较当前路径和两个候选 ASR/文本组合。记录：转写 WER、专名准确率、时间戳可回听程度、无依据事实新增数、家人修订分钟数、章节接受率、失败率及每个被接受章节的总成本。WER 低不等于传记忠实；家庭最在意的一处人名错误可能比十处虚词错误更严重。

上线前，测试样本中严重编造不得带入最终确认稿；模型不确定处必须能被家人找到并纠正。报告样本分子/分母，不能把少量测试零错误宣传成永不出错。

### 6.5 权限与隐私有具体待核查事项

ASR 路由接收调用者传入的 `storagePath`，随后使用 Supabase admin 下载（`:66–71`）；该分支未见对象归属检查。身份已登录不等于有权读取任意对象。应在扩大试点前，用两个测试家庭验证对象级授权。这里是静态代码风险，不是已证实的数据泄露事件。

隐私页仍写 “Last updated: January 2024”，一处说不向第三方转移个人信息，另一处又写使用第三方转录等服务；实际还有浏览器识别、SiliconFlow/OpenRouter 等处理路径。条款与数据流需一致，说明处理者、用途、保存/删除、跨地域安排与退出路径，而不是笼统写“只有家人能看到”。

官方 API 不用于训练、无滥用监控留存、某功能没有应用状态留存，是不同概念；代理路由也可能增加处理者。不能把一家厂商某端点的数据政策套到所有路径。

[口述历史协会伦理声明](https://oralhistory.org/oha-statement-on-ethics/)强调知情同意、讲述者审阅与发布前批准，并允许删除、限制、澄清或不公开。对 UR Saga 的实际启示是：将录音、家庭共享、公开贡献、模型改进授权分开；可公开不代表可以撤回互联网上所有已被复制的内容。这是口述历史实践依据，不是本次完成了法律合规认证。

## 7. 商业模式：卖完成结果，单独核算长期责任

### 7.1 当前定价体系应先统一

代码里同时存在至少两套思路：

- `components/purchase/pricing-cards.tsx:254` 与 `lib/payments/catalog.ts:11`：$99/$149/$249，一次购买、项目/席位资源包。
- `packages/shared/src/config/service-plans.ts:24`：$129/$199 年度、$179 十八个月、$499 lifetime（用100年天数表达）。

这不是两套都已经在售的证明，但说明产品、页面、权限和账单需要同一份商品定义。用户应该一眼理解：谁来讲、能讲多久、最终得到什么、之后还能否读取、继续录音如何收费。项目券、协调员席位、钱包不适合做主要购买语言。

### 7.2 三种可测试模式

| 模式 | 待测商品 | 价格假设（美元） | 何时值得做 |
|---|---|---|---|
| 数字短项目 | 四周、1位讲述者、约120分钟以内、原声＋确认文本＋PDF | $39 vs $59 | 最快验证能否完成和愿不愿付款；仍需检验没有纸书的价值 |
| 实体礼物 | 明确记录期、指定精装书规格、原声及文本导出 | $99 vs $129 | 取得印刷/配送报价且交付可控后，与 Remento 正面对照 |
| 协助完成服务 | 有人帮助选题、检查故事、排版交付，限定人工小时与修改轮次 | $199 vs $299 | 当家庭买的是完成服务，且人工成本能覆盖 |

以上都是**实验假设**，不是推荐立即推出三个套餐。先选一个主要承诺，避免小样本被多个定价、渠道与交付物同时分散。

之后可以收取新增访谈/下一季故事的服务费。现有成果可独立导出，云端持续托管的范围与成本另说明。不要依赖锁住旧回忆促进续费；竞品已普遍强调停订后的访问/导出。

### 7.3 真实成本可能主要来自人工和交付

`每单获客后贡献 = 净收入 − 支付/退款 − AI与录音处理 − 存储/下载/通信 − 印刷配送 − 人工支持 − 长期服务准备 − CAC`

商业专题用 $99 实体套餐做了两种**假设**：轻支持情况下获客前贡献约$46.47；支持和配送较重时只剩$10.80。若同样花$25获客，分别剩$21.47与亏损$14.20。它们不是供应商报价，而是说明为什么 API 变便宜仍可能不赚钱。

需要特别记账的项目：未激活礼物的后续义务、印书兑换、重新排版与补寄、家庭技术支持、音频长期读取与备份。免费转写或便宜 LLM 不能覆盖这些成本。公司固定成本和研发投入还需另算，不能把单笔正贡献当成公司盈利。

### 7.4 获客应和完成率一起测

首轮以美国为主要付费试点、两个获客来源；在已有声音整理与家人共同讲述中分组比较任务，再分步测价格，避免同时改变所有变量。Facebook/Instagram可测试具体成品演示与社区合作；Reddit主要帮助发现问题和反例；Threads补充自然家庭行为；X观察原声与AI争议。**这些是渠道实验分工，不是已测得的ROI排序。** 分别记录成本、参与意愿、完成、回听和退款，避免礼物卖出但亲人完全不使用。

不建议一开始买大量泛 AI 流量。机构合作可以带来信任，但销售、培训、信息处理和工作人员时间也可能让成本增加；先少量访谈和人工试点，不立即另建机构 SaaS。

当前没有足够一手数据估计本项目市场份额或 TAM。更有用的起步模型是：合格触达数 × 实际付费率 × 长辈参与率 × 完成率 × 每单贡献。每个参数都用试点更新，不拿泛老龄人口乘客单价冒充可获得市场。

## 8. 下一步：用六周获得决策证据

以下是试点顺序和粗粒度时间盒，不是工程工期承诺。若关键录音/授权/导出门槛未达到，付费真实家庭测试应顺延；期间仍可做访谈、价格理解和虚构素材测试。

| 阶段 | 工作 | 要交付的证据 |
|---|---|---|
| 第1周：统一事实 | 当前功能承诺表、主录音路径、AI供应商数据流、商品定义；访谈约10组子女/长辈 | 知道家庭为何想做、为何没做、愿保存什么；无依据承诺清单 |
| 第2周：完成最短链路 | 恢复、真实转写、错误状态、对象权限、原声下载；使用虚构素材验证 | 另一设备离线能读和听；坏网/重开可恢复；无mock进入真数据 |
| 第3–4周：小规模交付 | 约8–12家庭试点；达到门槛后招募真实付费家庭；允许人工补位但计时 | 首次独立录音、第二次故事、家庭审阅、实际成果、全部人工工时 |
| 第5周：比较价值与价格 | 相同来源分批测一个主要承诺和两个价位；给潜客看真实成品 | 付款/拒付原因、对纸书与数字的偏好、退款和每单贡献 |
| 第6周：做继续/收敛决定 | 对照先设门槛，回访未完成家庭 | 判断是入口问题、动机问题、商品问题、AI质量问题或经济问题 |

建议预先登记的早期门槛（**非行业基准、非统计显著结论**）：

- 约10位长辈中至少8位能独立完成第一次短录音；独立完成和有人帮助必须分别报告。
- 约10个付费家庭中至少6个在四周内收到并认可首份作品；不以创建了项目或录了音代替完成。
- 在声明支持的故障测试中，已经确认保存的录音没有丢失；所有测试家庭能离线打开交付包。
- 严重事实改写在最终确认前得到处理；参与者知道谁能看到故事。
- 每单收入能覆盖真实服务/交付成本，并为一个可测试的获客成本留下空间。

小样本应报告“8/10”而不是只写80%。这些门槛用于避免无方向开发，不足以宣布找到产品市场匹配。第二个故事率与第三周实际使用可解释完成率，不宜单独当作长期留存。

### 如何根据结果调整

| 观察到的结果 | 更合理的动作 |
|---|---|
| 子女付款但长辈不参与 | 换邀请方式、问题来源、共同采访或电话协助；不要只增强文案生成 |
| 愿意录音，但不认可成稿 | 优先原声忠实性、审阅、编辑风格与来源回听 |
| 喜欢成果但不愿付款 | 比较免费替代和竞品商品，收窄购买触发点/交付物；不靠堆功能推测价值 |
| 只有重人工陪同才能完成 | 将其视为服务业务重新定价与核算，不伪装成低成本自助 SaaS |
| 完成率与单位经济均可接受 | 才扩大渠道和自动化，随后测试实时主持、纸书或下一周期服务 |
| 多轮试点仍无付款或参与证据 | 暂缓大规模开发，保留技术资产，重新定位或停止该商业方向 |

## 9. 建议的投入顺序

**第一优先：**录音不丢、真实转写、真实状态、对象权限、完整下载、承诺一致。它们是家庭信任与商品成立的底线。

**第二优先：**一个好问题、低负担邀请、原声核对、短期作品、亲人回应。它们决定是否开始和完成。

**第三优先：**用评测选择 AI，后台可靠运行，降低每份被认可作品的纠错与支持成本。

**获得付款/完成证据后：**实体书合作、实时语音主持、电话渠道、更多国家。公共记忆库则应单独验证授权意愿和公共价值，不作为当前家庭商品成败的前提。

项目现在最有价值的下一步，是把已有的大平台收敛为一项可以完成的小服务，用真实家庭和真实账单验证。这样既保留已做工作的价值，也能尽快知道是否值得继续扩大投入。

## 10. 后续仍需补充的事实

1. 确认首个可实际触达的付费国家；当前建议美国先测数字成果，渠道优势可改变先后。
2. 已有真实用户、付费/退款、邀请与录音漏斗；本次未取得，不等于断言它们不存在。
3. 生产环境实际模型、供应商区域、迁移应用与错误日志；仓库默认不等于线上配置。
4. 一次完整家庭操作和一次离线下载验收；本次静态审查不能替代。
5. 印刷规格、实际运费、税费、短信/电话和客服工时的报价或实账。

建议继续以本报告作为工作基线，将新数据补到对应假设，而不是再增加一份无法与代码和经营事实对照的宏大 PRD。
