# T01两入口观察脚本与记录模板

2026-10-13 · 准备完成，招募/观察未执行：参加家庭0户、已观察0户。配套[本地原型](../prototypes/2026-10-13-two-entry/index.html)、[原型设计](../superpowers/specs/2026-10-13-upgrade-t01-prototype.md)。负责人尚未提供可触达渠道或研究时间；本次未联系、邀请或向任何家庭发送消息。

## 研究问题

1. 讲述者能否从邀请回到原问题，清楚谁能听、下一步做什么？
2. 是否区分此设备有副本、正在上传、云端完整确认；出错时会不会误以为原声丢失或已备份？
3. 文字整理失败后，是否能继续保留原声、找到重试，不重复录制？
4. 核对姓名/年代时是否能找到对应来源；能否保留不同记忆，不把有争议年份当成确定事实？
5. 是否理解批准与下载不同；原件缺失时能否发现交付不完整？

这是交互理解研究，不测真实录音、ASR准确率、离线完整导出、付费转化或7/28天完成率。原型全部使用虚构材料，下载只产生带PROTOTYPE标记的演示收据，不含声音。

## 样本和安排

目标6–8个家庭，每户含组织者，尽量有实际讲述者。覆盖较低/较高数字熟练度和自主/家人陪同两种完成方式；记录实际构成，不把招募目标写成已达配额。不按国家强行分组，沿用可触达英语家庭优先的D05。

每户45–60分钟。同一户走两入口，交替入口顺序：家庭顺序中的奇数先导入后邀请，偶数先邀请后导入；实际偏离记录理由。两入口学习迁移会影响第二次表现，首入口结果单列。家庭为观察单位；同户两人不充作两个独立家庭。

观察前说明本地演示与自愿退出，取得研究与记录方式的单独同意。默认仅笔记，不录音/录像；如需录制须另行同意并先落实访问/保留/删除安排。使用家庭代号，不在Git记录真实姓名、联系方式或私人故事。参与者随时可以跳过问题或结束，不要求解释原因。

## 主持流程

先让参与者读页面原型说明；主持人说明这次验证界面理解，故障由演示按钮模拟。执行任务时先请参与者说预期，操作后再说看到什么；不要提前教下一按钮。研究操作区由主持人使用，参与者主要看英语产品预览。

| 时间 | 主持话术/任务 | 观察内容 |
|---|---|---|
| 0–5分钟 | “这里都是虚构示例，没有上传或录音。你想停止时随时可以。”询问通常使用什么设备、是否需要家人陪同 | 研究同意、设备、数字熟练度与帮助方式 |
| 5–15分钟 | 导入：“假设你已有一段声音，想放进家庭故事。请从示例开始，做到你认为可以放心离开的位置。” | 是否先核实素材用途；离开前指认本机/云端；是否将上传中误判完成 |
| 15–25分钟 | 邀请：“Sam邀请你讲一讲第一个家。请进去、完成演示认证，再告诉我接下来准备讲什么、谁会听到。” | 问题返回是否连续；认证是否被理解为公开分享；自主/陪同分别记录 |
| 25–33分钟 | 中断：“假设刚才页面中断了。现在有哪些内容能找回？”主持人分别设置已有片段/没有片段；随后设置上传失败 | 区分演示恢复和真实刷新；是否发现没有副本；重试是否被误解成重新录音 |
| 33–40分钟 | 整理失败：“声音已经完整确认，但文字没整理出来。你会怎么办？” | 是否知道原声仍在；是否能找到重试；是否以为系统自动补了内容 |
| 40–50分钟 | 核对：“关于搬家的年份，家里人记得不一样。请处理这段话，再决定是否批准。” | 能否找到原声片段位置；编辑、保留双方记忆与跳过的差异；未解决严重项是否被理解 |
| 50–55分钟 | 下载：“你想把故事带走；现在系统报告缺少原件，你觉得下载里会有什么？” | 是否把演示收据当声音档案；缺件提示是否明确；是否会误报交付完成 |
| 55–60分钟 | “哪里最让你犹豫？你现在会怎样向家人解释保存和批准？” | 开放意见、最重要阻断、未预设的理解方式 |

只有参与者停滞或明确请求才提供帮助。记录第一次帮助之前的结果；帮助后完成单列，不能回填成独立成功。无须要求参与者按既定按钮完成所有任务；错误路径和退出本身是观察结果。

## 记录字段

每个任务一行，保留失败和未完成。时间采用实际秒数；原型中的假录音时长不作为完成耗时。

| 字段 | 含义 |
|---|---|
| session_id / family_code / date | 匿名研究编号、家庭单位与日期 |
| participant_role / digital_familiarity | 组织者/讲述者及自报数字熟练度 |
| device / OS / browser / viewport | 真实版本与显示大小，不能仅写“手机” |
| entry_order / task / assistance_mode | 两入口顺序、情景、自主或陪同 |
| expected_before / interpretation_after | 点击前预期、之后对本机/云端/整理/批准/下载的理解 |
| first_action / actions / time_seconds | 实际操作及耗时，可只记录关键路径 |
| help_count / first_help_at / blocker | 主持或家人帮助、首次帮助点、阻断描述 |
| outcome | independent / assisted / incomplete / skipped / withdrew |
| severity / observed_evidence / suggested_change | 严重度、实际行为/原话与拟改动分开 |
| consent_note / retention_location | 研究同意代号和受限笔记位置，不存私人正文 |

## 怎样汇总与决定改动

逐任务报告独立完成x/n、辅助完成x/n、退出/跳过/未完成数；n为实际开始该任务的家庭数。任务未开始单列，不能从样本里静默删除。两入口及入口顺序分层展示；n=0写“未观察”，不报0%通过。样本小，优先给出行为与原话，不推断总体市场比例。

必须修复的阻断：误以为未确认的云端资料已保存；无法识别原件缺失；无法从认证返回问题；有严重未解决事实仍批准；不能看懂中断后实际可恢复范围。记录重复发生与单例同样重要，不把罕见但严重问题按多数票忽略。

先修复阻断并用受影响任务复看；设计方向和原型表现不能自动提升成G0/G1通过。真实设备恢复、Storage隔离、供应商质量、完整原件导出分别按[质量门定义](../superpowers/specs/2026-10-13-upgrade-p0-gates.md)取证。收费和扩大试点仍服从G3/G4。
