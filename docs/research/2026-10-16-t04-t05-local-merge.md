# T04/T05：真实本地文件合并与持久 Worker

2026-10-16（Asia/Taipei）。本地链路实现、测试与最终独立复审均已完成；两处进程回收 P2 已关闭，未发现新增规格或代码质量问题。

本批按 [handoff](../HANDOFF-2026-10-13-upgrade.md) 与[实施计划](../superpowers/plans/2026-10-16-upgrade-t04-t05-merge.md)接通本地链路：冻结块清单 → 持久任务 → 文件读流 → 原始字节合并 → 实际解码 → 私有输出回读 → 受保护事务发布引用。

## 处理与发布边界

数据库只保存测试任务、清单与引用；pg-boss 消息只含任务 ID。源文件来自本次自建私有临时目录中的虚构音频，没有读取真实家庭资料。合并与解码在数据库事务外执行，心跳负责维持确切业务 attempt 和 queue claim；停止/失租信号传到文件读流及解码进程。

文件系统和数据库没有共同事务。输出先写入唯一的私有文件，回读大小与 SHA-256 后，数据库事务才在重新检查授权标志、取消/删除、租约、队列 claim 和输入绑定后提交产物引用。数据库引用是本实验的发布入口。提交前退出可能留下私有孤立文件；COMMIT 已发送但结果未知时不能删除文件并冒险破坏已提交引用。孤立文件不得由读取入口返回，也不自动复用，本批不实现长期孤立文件回收。

这套本地授权标志和测试表不代表真实 Supabase RLS、用途同意或资产表 adapter。解码成功也不能证明最后一个录音块已完整上传；真实会话封口仍需末块和清单版本的独立证据。

## 验证结果

最终真实合并[测试](evidence/2026-10-16-t04-t05-merge/worker-round2-verified.json) **52 场景 / 396 项断言，退出 0**，源码指纹与当前文件一致。测试使用 Node 22.22.2、PostgreSQL 14.17、pg-boss 12.37.1、pg 8.16.3 和 FFmpeg 7.1。

| 覆盖 | 实际证据 |
|---|---|
| 正常处理 | WebM / MP4 / Ogg，12 块数字排序，真实磁盘源块、原件字节保持、真实解码时长、输出 size/hash 回读、已发布引用再次读取 |
| 幂等与输入 | 同 ID 换清单及同幂等键换 ID 被拒；重复 envelope 只产生一份发布结果；项目/会话/资产/输入与处理器版本、清单及 attempt 绑定变化被拒 |
| 文件失败 | 缺块、同大小坏 hash、大小变化、symlink、FIFO、不可解码内容、输出缺失/篡改均不发布；字节与块数上限生效 |
| 取消与失效 | 准备后取消/删除/撤权，lease/queue attempt/queue job/business attempt 变化，最终事务内实际 lease 到期，读取中撤权后拒绝返回内容 |
| 崩溃与提交 | 子进程在准备后、COMMIT 前被实际 SIGKILL；旧 Worker 迟到不能覆盖替代结果；COMMIT 回执故障分别验证实际提交与实际未提交；私有孤立文件不暴露/不自动复用 |
| 生命周期 | 真实源流打开期间用可取消检查点测试 abort/timeout；runner 处理期间保持心跳，停止/撤权/删除结束工作；实际 FFmpeg 在 `-re` 输入节流下运行、续心跳并响应关闭 |

`-re` 通过本地 shell `exec` 包装器加入，是明确标记的输入节流，不是六秒 CPU 解码负载或长录音验收。6.2 秒/10 秒读检查点暂停也仅控制故障时序。COMMIT 回执故障通过客户端 query 包装器注入，同时分别真实执行/不执行 PostgreSQL COMMIT。所有夹具细节保存在逐场景 evidence 中。

取消 helper 新增 **14 项**测试，定向最终 **55/55**；有确认 red 与 green 输出，[Task 1 独立审查](evidence/2026-10-16-t04-t05-merge/task-1-review.md)通过。项目 `npm run verify` 退出 0：**75 套 / 716 项**、类型、lint 和 **175 页**构建通过；shared **4 套 / 16 项**、infra **7 项**通过，[项目检查](evidence/2026-10-16-t04-t05-merge/project-checks.json)记录命令、退出码和应用源码指纹。构建前内容已恢复到 `next-env.d.ts`。

前批 39/307、300 秒合成等待和 56 项真实解码仍属于各自历史证据。本次没有重跑无关的五分钟 soak；本次对修改后的 Worker 重跑[原 T05 全量回归](evidence/2026-10-16-t04-t05-merge/regression-final.json)，**39 场景 / 307 项断言、退出 0**；所有所属 supervisor 进程组与 runner PID 均已清理。两组主验证均记录零残留所属进程/组、数据库停止、临时目录删除和零清理错误。

[首轮独立审查](evidence/2026-10-16-t04-t05-merge/review-initial.md)确认一个 P2：新增未登记进程组的 worker/runner 被 harness 强杀后可能留下 FFmpeg。已将 worker/direct runner/supervisor 都登记为独立进程组，保留父进程退出后的组标识，协作停止后再有界强制回收；同一 harness 进程内的直接处理也接入共享取消信号并等待完成。外部观察器另执行 **6/6** 组合：runner、worker、direct × fatal、SIGTERM，在实际 FFmpeg `-re` 解码中挂起子进程，并检查 harness 退出后的真实 PID、进程组、数据库和临时目录，见[最终异常清理证据](evidence/2026-10-16-t04-t05-merge/cleanup-round2-verified.json)。所有最终组合无需观察器救援，预期异常退出 1、预期 SIGTERM 退出 143 均符合记录。父进程已退出时系统可能自行回收孤立组，测试检查组登记与最终进程消失；父子仍挂起时额外要求实际执行组级强杀。增量复审结论见最终汇总。

[第一轮增量复审](evidence/2026-10-16-t04-t05-merge/review-round1.md)确认原 P2 已处理，同时发现观察器自身超时/非预期退出会在读取 raw evidence 前丢失所有权，并存在无界等待。第二轮修复通过所属 harness IPC 提前记录私有目录、集群和后代，保留所有权到 IPC 排空后，再协作停止、按确切所属组/PID 兜底、独立 `pg_ctl stop/status`，确认全部停止后才删除目录。缺失 raw evidence 不再妨碍清理；未确认停止会保留数据并报告失败。

新增[观察器自身故障验证](evidence/2026-10-16-t04-t05-merge/observer-round2-verified.json) **2/2**：超时及 harness 非预期退出 17；另有[观察器实际 SIGTERM](evidence/2026-10-16-t04-t05-merge/observer-round2-verified-interrupt.json) **1/1**，预期退出 143。三个场景均在实际解码器和私有数据库仍存活时触发，raw 文件故意缺失，最终由提前收到的 IPC 所有权完成独立数据库停止，进程/组全部消失且临时目录移除。最外层观察器自身被 SIGKILL 仍无法执行清理，不能据这些测试承诺所有最外层强杀都能自动收尾。

所有最终运行源码指纹（包括观察器及六份嵌入的异常清理原始报告）与当前源码一致。[最终增量独立复审](evidence/2026-10-16-t04-t05-merge/review-final.md)确认两处 P2 均已处理，规格与代码质量新增问题均为 0；命令退出码和最终验收文件见[汇总](evidence/2026-10-16-t04-t05-merge/verification.json)。此前原回归只记录、未执行独立观察器时曾保留旧观察器 hash 的版本，属于历史；最终 `regression-final.json` 已在本轮所有修正后重跑。
