## 中断 WebM

真实 Chrome 的一分钟分块包含 1,000 个完整音频块，末尾另有下一 Cluster 标识的首字节 `1f`。原 FFmpeg 会输出完整 60 秒 PCM，同时报告 `File ended prematurely`；既有严格解码器正确拒绝该输入。

新增的有限 EBML 解析器只识别已完整保存的 WebM 结构和无 lacing 的 SimpleBlock。它在独立临时副本内关闭未知 Segment／Cluster 长度，只去掉能够逐字节证明属于下一 Cluster 的不完整容器头；音频块内部截断、其他尾部和不支持的结构不会走该修复路径。原始分块、上传原件及其 SHA256 均不改写，严格 FFmpeg 诊断拒绝规则保持不变。

原始一分钟样本与封闭容器副本的解码 PCM 完全一致。被截掉一个音频包字节的反例仍拒绝。恢复页进入继续保存后仍显示“结尾可能缺失”的范围说明；成功恢复的是持久分块覆盖的约 60 秒，不能宣称包含刷新前尚未落盘的剩余约 5 秒。导出的恢复原件保留原始容器字节，第三方严格解码工具可能仍报告该容器尾部诊断。

最终 Chrome 中断矩阵覆盖：原生分钟分块、刷新恢复、断网保留、账号切换取消、reserve／seal／confirm 已提交但响应丢失、处理中保留、重复保存同一故事、实际回放、本地 IndexedDB 清理回滚及重试。生产项目权限检查现在也在编译图中；仅认证和数据库／Storage 传输边界为本地适配器。

## 空库迁移

启动 schema 缺少历史安装已有的 `project_members`、`story_artifacts`、`public_archive_entries`、`waitlist`。前序 tracked migrations 创建的 `agent_artifacts`、`public_contributions` 和 `waitlist_signups` 是不同表，不能作为别名混用。

bootstrap 现在补齐四个兼容关系，保留已恢复的历史行。新前向迁移 `20261107000001_legacy_compatibility_acl.sql` 关闭旧 blanket grants 重新开放的客户端访问，并启用 RLS。验证以真实 PG17.4、pgcrypto 和 uuid-ossp 执行 bootstrap 与全部根迁移；兼容表预先写入历史行与宽松策略后再跑 bootstrap，最终完整行不变，anon／authenticated 的实际查询和七种表权限均被拒绝。

恢复脚本改为按文件名顺序执行全部根迁移，遇到首个失败立即停止。命令级反例确认后续文件不会继续执行。完整 Supabase 平台仍由本地 auth/storage schema 和传输适配器表示；本轮没有声称托管服务或远端迁移合格。
