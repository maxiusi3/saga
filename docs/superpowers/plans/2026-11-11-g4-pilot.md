# G4 试点台账与决策分析收口

本批承接已获准的本地 PostgreSQL 17.4＋Chrome Web 验收。G3 基线为 `c0669e8` 工作区快照，1265 个源码文件逐一复核无漂移；保留既有未提交改动。本地工程进度起点约 92%：T00–T13 估时中值 82.5 人日，T13 中值 6.5 人日。比例是计划权重估算，不是正式发布或真实试点进度。

## 已确认范围与缺口

依从总计划 §7.1、§10.2–10.3。旧 G4 只有可手工填数的表、聚合函数和只读接口；四户也可能触发扩大建议，未验证样本来源、完整观察窗、成本完整性或真实启动同意。旧 22 项数据库断言不能代表纵向试点通过。

本批交付运营人员可实际使用的、带证据索引的版本台账和 HTML/JSON 报表。运营端使用现有服务器管理凭证，不在客户端存储该凭证。录音、批准、履约、支付、人工工时及访谈等异构证据由运营逐项核对录入，禁止推断“下载即回听”或“标价即支付”。这是人工对账入口，不宣称自动遥测。

## 实施顺序

1. **修正分析引擎，先写反例。** 观察/合成/未分类分开；显式单批次与封存招募名单；按真实家庭去重；全部 7/28/14 天窗口成熟后才形成建议。至少 20 户，真实付费不足本身可形成价格重验建议。按价格与版本/渠道/国家/支持方式分层，保留退出、未完成和退款。未知成本不视作零成本，人工费率显式给出，全批贡献含免费家庭、CAC、履约与托管准备。家庭每篇修订与每户工时分别报告。
2. **建立版本台账。** 新增独立迁移，旧数据保持未分类。服务端管理接口校验字段、时序、证据类型、费用、观察来源；数据库 RPC 保证幂等、版本冲突、身份不漂移和封存名单。每次改正保留旧版及操作者/原因/证据索引。实际项目/故事清除同时删除试点记录及所有版本，批次仅保留无法反查家庭身份的删除数量，存在样本损失时阻断自动通过；不保留故事正文、邮箱或姓名。
3. **提供实际运营入口。** POST 管理接口用于记账和关闭招募；GET 按批次及观察类型返回 JSON/HTML。服务器脚本从环境变量取管理凭证，读取本地 JSON 输入或保存报表；管理数据一律 no-store，普通登录不可读取。合成批次的 HTML 明确显示不构成真实试点通过。
4. **完整迁移与 Chrome 验收。** 复用 `experiments/g1-local/verify-migrations.mjs`，验证实际 PG 角色/权限、重复/并发/冲突、关闭名册、历史修正、删除解除关联、1000 条以上分页边界。Chrome 打开实际管理报告路由，检查无样本、合成数据、分母及结论；保留截图和源哈希。
5. **审查与收口。** 独立审查规范与代码，修复问题，执行 `npm run verify`、shared/infra 和 G3 回归；记录当前范围内的证据、局限和源码快照。所有改动保留未暂存，不提交、不推送、不部署。

## 验收边界

- `g4GateReady` 只可用于具有证据的真实观察；合成数据最多形成 `simulationReady`。
- 20–30 户、真实成交、实际 4–6 周观察、真实回听/访谈以及供应商账单不能从本地测试中取得。本批不伪造，也不代替负责人作扩大/转向/停项决定。
- 隐私删除后仅剩批次级删除数量，没有用户/项目可逆关联；统计口径披露样本损失。这不替代上线前的研究同意与保留条款。
