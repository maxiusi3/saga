# T04 SmartRecorder 本地会话接入

日期：2026-10-14（Asia/Taipei）。承接 T04 本地契约和 handoff 的下一步。

## 全局约束

- 保留当前分支及前序未提交变更；不提交混合批次，不部署、不推送、不执行远端迁移或真实供应商调用。
- 只接入浏览器录音会话与本地持久化。现有 Storage 上传仍是临时块，不能据此确认资产、删除本地块或声称容器可解码。
- 本地会话绑定项目和当前登录用户，实际 MIME 取自 MediaRecorder；storyteller 不替代当前登录身份。

## Task 1: 接入和契约测试

1. 为 SmartRecorder 写 mock 浏览器/IndexedDB/Storage 契约测试并观察 RED。
2. 使用已存在的 recording-session / recorder-db 能力，必要时抽取一个小型会话协调模块；保存会话成功才开始录音，缺少项目/登录身份、无支持格式和存储失败应真实报错并释放设备。
3. 从浏览器显式支持的候选选择 MIME，保存 recorder 实际 MIME，并以实际格式生成临时块文件名和上传类型。拒绝无浏览器能力证据的假回退。
4. 非空块按会话固定身份计算真实 SHA-256、保存 Blob/大小/hash，持久化提交完成后才允许上传。上传成功只标记 uploaded；失败保留 pending；补传跳过 uploaded，重复触发不并行上传同一块；慢上传不得阻塞后续块落盘。
5. 正常停止、异常、页面退出/卸载保留可恢复的未确认会话，最终块处理完成前不得误报已持久化；旧回调和在途启动不能污染重录/新会话。不会因网络语音识别失败自动丢弃当前录音。
6. 验证实际 MIME、会话身份、先落盘后上传、失败/补传保留副本、中断/卸载、最后一块与重录隔离。保留现有页面回归。

## Task 2: 验证与交接

1. 独立审查本批改动与相邻调用；处理实际问题。
2. 运行 npm run verify，保存结果，按验证前快照恢复生成的 next-env.d.ts 并检查差异。
3. 更新 T04 实施记录、综合计划、handoff 和索引。明确浏览器 mock 不等于真机验收，远端会话、合并/解码、确认和恢复界面仍未完成。
