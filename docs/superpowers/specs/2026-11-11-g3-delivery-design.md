# G3 archive delivery, source search and payment fulfillment

This implements the already confirmed T09–T12 upgrade plan after G2. The user requested continued G3 execution under the same local Chrome acceptance standard. Synthetic local accounts, native PG17.4 and installed Chrome are authorized; live provider payments, hosted migrations/deployment and human/device qualification are not part of local acceptance. Preserve all inherited work in the current branch without staging, commits or push.

## T09: deliver the approved rendition

The present exporter reads legacy story text, truncates the PDF and invents a fresh version-one publication on every download. Replace these behaviors with a source-checked, persisted publication snapshot bound to the latest approved G2 revision for each reviewed story. Keep raw source transcripts separately labelled in the archive; unapproved drafts must never appear as approved biography. Unreviewed imported stories may retain a clearly labelled source-only export. Preserve original media hash verification, current membership and G1 project/story/asset/session deletion checks before release. A new approval creates a new snapshot; corrections never overwrite a prior approved publication. Repeated downloads of an unchanged snapshot do not extend a purchased hosting period. Schedule metadata is not evidence a reminder was sent.

The reading PDF must paginate all supplied prose, preserve supported Unicode and render actual long-form samples. Fail explicitly for unsupported content rather than silently replacing or truncating it. Keep independently readable offline HTML, original/derived media and machine-readable source/provenance/revision data. Large archives require a durable job and bounded disk/streaming processing outside a page request, with status/retry, source revalidation and protected download; do not raise the in-memory request limit as a substitute. Persisted publication and job records must participate in G1 erasure and restore replay.

## T10: search authoritative source records

Remove reliance on manually seeded, stale index prose. Query or atomically refresh versioned authoritative transcript/revision/assertion data with project membership, current source identity, ready audio and deletion checks. Return literal source excerpts or labelled family supplements, never describe lexical matching as semantic truth. Only original timed segments may provide audio links; unaligned text, edits and disputes preserve null timing. A corrected source replaces active search content while approved history remains immutable. Reject stale, cross-story and forged index/source relationships. Bound query size, result size and database work, and deny revoked members. Support keyword/person/year/place search without invented model answers; any unavailable semantic model is explicitly unmeasured rather than simulated.

## T11: server-owned purchase and event identity

Present the agreed US$59 single-narrator package and 12-month hosting scope; remove lifetime/unlimited promises from the active purchase flow. Enable payment initiation only via explicit server configuration, initially using Stripe test mode for local acceptance. Persist stable order/request identities so repeated clicks and uncertain responses reuse one intent. Derive amounts, payer and package from the authenticated order/catalog; never trust client or webhook-supplied grant counts. Verify the raw Stripe signature, event type, mode and exact payment identity/amount/currency before fulfilling.

Serialize duplicate/concurrent/out-of-order event processing. Cancellation/failure cannot grant; refund before success suppresses late grants; a completed refund revokes only rights attributable to that source, preserving unrelated purchases. Integrate with the existing trusted invitation entitlement ledger rather than creating spendable legacy wallet credits with no trusted source. Record status and show it through an authenticated UI; client redirects are not proof of payment. Real charging remains disabled until live commercial terms, actual provider configuration and release gates are completed; pending payment/hosting/renewal policies must be disclosed, not invented.

## Verification

Use real route handlers, SDK and complete bootstrap/migration schema in disposable native clusters. Chrome exercises approved story → search → source seek → archive download → offline HTML/PDF, purchase intent/status and signed controlled events. Validate two-family isolation, revocation, deletion, backup/restore, long archive/PDF completeness and retry/race failures. Controlled Stripe transport proves integration mechanics, not real settlement. Preserve first behavioral failures and final logs/screenshots/source hashes. Historical G3 device names, PDF header checks and hand-seeded SQL rows remain historical evidence, not new browser or payment qualification.
